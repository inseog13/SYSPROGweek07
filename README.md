## 1_pipe_basic 파이프를 이용해 문자열을 대문자로 변환하는 프로그램
현재 코드: 부모 → 자식 (문자열 한 번 전달)

수정할 코드: 부모 → 자식 → 부모 (문자열을 대문자로 변환한 뒤 반환)

1. 파이프 하나를 추가

원본
```
int fd[2];
```

수정본
```
int fd[2];
int fd2[2];
```
fd는 부모에서 자식으로, fd2는 자식에서 부모로 데이터를 전달합니다.


2. 실행 인자를 받도록 수정

원본
```
const char *msg = "안녕, 자식 프로세스!";
```

수정본
```
const char *msg = argv[1];
```


3. 자식이 사용하지 않는 파이프 끝을 닫음
```
close(fd[1]);
close(fd2[0]);
```
자식은 fd에서 읽고 fd2에 쓰므로 반대쪽 끝은 필요하지 않습니다.


4. 문자열을 대문자로 변환
```
for (int i = 0; i < n; i++) {
    buf[i] = (char)toupper((unsigned char)buf[i]);
}
```
자식이 받은 문자열을 한 글자씩 대문자로 바꿉니다.


5. 자식이 부모에게 결과를 돌려줌
```
write(fd2[1], buf, n);
```
원본에는 없던 코드입니다. 두 번째 파이프에 변환된 문자열을 기록합니다.


6. 부모가 반환된 문자열을 읽음
```
char buf[4096];
ssize_t n = read(fd2[0], buf, sizeof buf - 1);

if (n > 0) {
    buf[n] = '\0';
    printf("[부모] 반환된 문자열: %s\n", buf);
}
```
기존 부모 코드에는 전송 후 자식의 종료를 기다리는 부분만 있었지만, 이제는 자식의 응답을 읽는 부분이 추가됐습니다.

## 2_pipe_dup2 파이프와 dup2()를 이용해 두 명령어를 연결하는 프로그램
현재 코드: ls의 출력을 파이프로 전달해 wc -l로 줄 수 계산
수정할 코드: ./2_pipe_dup2 ls -l : wc -l처럼 실행 인자로 두 명령어를 입력받고, :를 기준으로 구분해 파이프로 연결

1. 실행 인자를 받도록 수정

원본
```
int main(void)
```

수정본
```
int main(int argc, char *argv[])
```
기존에는 ls와 wc -l이 코드에 고정되어 있었지만, 수정본에서는 실행할 때 명령어와 옵션을 입력받습니다.
예를 들어 ./2_pipe_dup2 ls -l : wc -l을 실행하면 argv에 프로그램 이름, ls, -l, :, wc, -l 등이 저장됩니다.


2. 기존에 ls로 고정되어 있던 실행 방식을 변경

원본
```
execlp("ls", "ls", NULL);
```

수정본
```
for (i = 1; i < argc; i++) {
    if (argv[i][0] == ':' && argv[i][1] == '\0')
        break;
}
```
원본은 ls 명령어를 직접 지정했지만, 수정본은 입력받은 인자 중 :가 있는 위치를 찾습니다.
: 앞쪽은 첫 번째 명령어, 뒤쪽은 두 번째 명령어로 사용합니다.


3. 잘못된 입력 확인

수정본
```
if (i == argc || i == 1 || i == argc - 1) {
    fprintf(stderr, "사용법: %s 명령어1 인자... : 명령어2 인자...\n", argv[0]);
    return 1;
}
```
:가 없거나, 앞이나 뒤에 명령어가 없는 경우에는 사용법을 출력하고 종료합니다.


4. :를 기준으로 명령어 배열 분리

수정본
```
cmd2 = &argv[i + 1];
argv[i] = NULL;
```
cmd2는 두 번째 명령어가 시작하는 위치를 가리킵니다.
그리고 :가 있던 위치를 NULL로 바꾸어 첫 번째 명령어의 인자 배열을 끝냅니다. 이렇게 하면 execvp()가 각 명령어의 인자를 올바르게 구분할 수 있습니다.


5. 첫 번째 자식의 표준출력을 파이프로 연결

원본
```
execlp("ls", "ls", NULL);
```

수정본
```
close(fd[0]);
dup2(fd[1], STDOUT_FILENO);
close(fd[1]);

execvp(argv[1], &argv[1]);
```
execvp()를 사용하면 ls -l처럼 명령어와 옵션을 실행 인자로 전달할 수 있습니다.


6. 두 번째 자식의 표준입력을 파이프로 연결

원본
```
execlp("wc", "wc", "-l", NULL);
```

수정본
```
close(fd[1]);
dup2(fd[0], STDIN_FILENO);
close(fd[0]);

execvp(cmd2[0], cmd2);
```
이제 첫 번째 명령어의 출력이 파이프를 통해 두 번째 명령어의 입력으로 전달됩니다.

## 3_fifo_read / 4_fifo_write FIFO로 메시지를 주고받는 프로그램

현재 코드: 3_fifo_read.c는 FIFO를 통해 메시지를 받고, 4_fifo_write.c는 FIFO를 통해 메시지를 전달함

수정할 코드: 받는 쪽과 보내는 쪽을 한 쌍으로 구성하고, 받는 프로그램을 먼저 실행해 메시지를 수신한 뒤 FIFO를 삭제하도록 구성

1. FIFO를 생성하도록 구성

수정본
```
if (mkfifo(FIFO_PATH, 0666) == -1 && errno != EEXIST) {
    perror("mkfifo");
    return 1;
}
```
받는 프로그램은 mkfifo()를 사용해 /tmp/sysprog_fifo라는 이름의 FIFO를 생성합니다.

mkfifo()가 실패하더라도 이미 FIFO가 존재해서 발생한 EEXIST 오류라면 기존 FIFO를 그대로 사용합니다. 그 밖의 오류가 발생하면 오류 메시지를 출력하고 종료합니다.

FIFO는 파일 시스템에 이름을 가지므로 부모와 자식 관계가 없는 별개의 프로그램끼리도 데이터를 주고받을 수 있습니다.


2. 받는 쪽을 먼저 실행하고 상대방을 기다림

수정본
```
printf("보내는 쪽을 기다립니다... (%s)\n", FIFO_PATH);

int fd = open(FIFO_PATH, O_RDONLY);
if (fd == -1) {
    perror("open");
    return 1;
}
```
받는 프로그램은 open()을 사용해 FIFO를 읽기 전용으로 엽니다.

기본 설정에서는 읽기 쪽이 FIFO를 열 때 상대방이 쓰기 쪽을 열 때까지 기다립니다. 따라서 받는 프로그램을 먼저 실행해 두고 다른 터미널에서 보내는 프로그램을 실행해야 합니다.


3. FIFO에서 메시지를 읽도록 구성

원본
```
ssize_t n = read(fd, buf, sizeof buf - 1);
if (n > 0) {
    buf[n] = '\0';
    printf("받은 메시지: %s\n", buf);
}
```

수정본
```
ssize_t n = read(fd, buf, sizeof buf - 1);

if (n > 0) {
    buf[n] = '\0';
    printf("받은 메시지: %s\n", buf);
} else if (n == 0) {
    printf("받은 메시지가 없습니다.\n");
} else {
    perror("read");
}
```
기존 코드에서는 데이터를 정상적으로 읽었을 때만 결과를 출력했습니다.

수정 후에는 read()의 반환값에 따라 세 가지 상황을 구분하도록 변경했습니다.

정상적으로 문자열을 읽었을 경우에는 문자열 끝에 널 문자 '\0'를 추가하여 printf()로 출력할 수 있도록 했습니다.


4. 보내는 쪽에서 실행 인자로 메시지를 전달

수정본
```
const char *msg = (argc == 2) ? argv[1] : "기본 메시지";
```
보내는 프로그램은 실행할 때 입력한 인자가 있으면 그 문자열을 사용하고, 없으면 "기본 메시지"를 사용합니다.


5. 보내는 쪽에서 FIFO에 메시지 기록

수정본
```
int fd = open(FIFO_PATH, O_WRONLY);
if (fd == -1) {
    perror("open (받는 쪽을 먼저 실행했는지 확인)");
    return 1;
}

if (write(fd, msg, strlen(msg)) == -1) {
    perror("write");
    close(fd);
    return 1;
}
```
보내는 프로그램은 FIFO를 쓰기 전용으로 열고, write()를 이용해 메시지를 전달합니다.

받는 프로그램이 먼저 실행되어 있지 않으면 open()에서 기다릴 수 있습니다. 따라서 과제 조건에 따라 받는 프로그램을 먼저 실행해야 합니다.


6. 통신이 끝나면 FIFO를 닫고 삭제

받는 쪽 수정본
```
close(fd);
unlink(FIFO_PATH);
return 0;
```
메시지 수신이 끝나면 close()로 파일 디스크립터를 닫고, unlink()로 FIFO의 이름을 파일 시스템에서 제거합니다.

FIFO는 파일 시스템에 이름이 남는 특성이 있으므로 사용이 끝난 뒤 삭제하는 작업이 필요합니다. 이 과제에서는 받는 프로그램이 메시지를 읽은 뒤 FIFO를 삭제하도록 구성했습니다.
